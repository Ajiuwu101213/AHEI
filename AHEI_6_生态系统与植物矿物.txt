第一章  生态系统总览
================================================================================

1.1 食物链结构

    AHEI世界的生态系统由五个营养级构成完整的食物链：

    第一层——生产者（植物）：
        树木、灌木、草本、真菌、水生植物
        通过光合作用（模拟）将太阳能转化为生物质
        是所有食物链的基础

    第二层——初级消费者（食草动物）：
        小型：兔子、松鼠等（平原/森林）
        中型：鹿、山羊等（森林/丘陵/山地）
        大型：野牛等（平原）
        以植物为食，将植物能量转化为动物蛋白

    第三层——中级消费者（杂食者）：
        AHEI属于这一层
        既吃植物（浆果、水果、坚果、谷物）
        也狩猎小型动物（兔子、鱼等）
        偶尔可能同类相食（极端饥饿情况）

    第四层——高级消费者（捕食者）：
        伏击型：隐藏于灌木/岩石后
        追踪型：耐力持久
        飞行型：空中俯冲
        群猎型：2-3只协作
        捕食AHEI和食草动物

    第五层——分解者（微生物/真菌）：
        分解尸体、枯枝落叶
        将有机质回归土壤
        完成物质循环

1.2 物种数量动态平衡机制

    种群数量由捕食-被捕食关系和环境承载力共同调控：

    植物数量↑ → 食草动物数量↑
    食草动物数量↑ → 捕食者数量↑
    捕食者数量↑ → AHEI死亡率↑ → 食草动物数量↓ → 植物数量↑
    （捕食者数量也会影响食草动物数量）

    环境承载力：
        食物资源总量决定了各级消费者的最大种群容量
        超过承载力→饥荒→数量下降
        低于承载力→恢复→数量回升

    这个循环在季节周期的影响下不断波动，形成自然的动态平衡。

    在Godot中，生态数据存储在EcosystemManager（Autoload单例）中：
    ```gdscript
    # EcosystemManager.gd
    var plant_count: int = 0
    var herbivore_count: int = 0
    var predator_count: int = 0
    var ahei_count: int = 0
    
    func update_balance(delta: float) -> void:
        # 每帧或定时更新食物链平衡
        pass
    ```

1.3 季节对生态的周期性影响

    春季：
        植物发芽开花，食物开始增多
        食草动物繁育后代
        捕食者食物充足
        AHEI觅食容易，交配繁殖活跃

    夏季：
        食物达到年度峰值
        所有物种数量上升
        竞争加剧
        自然灾害（山火、洪水）概率上升

    秋季：
        果实成熟，是最佳收获季
        AHEI必须大量采集和囤积以过冬
        食草动物囤积脂肪
        储存不足的个体将在冬天死亡

    冬季：
        植物枯死或休眠，食物极度短缺
        食草动物数量大幅下降
        捕食者更凶猛（饥饿驱动）
        AHEI死亡率最高
        只有储存充足、巢穴保温良好的个体和部落能存活

1.4 生态事件链

    特定事件可能触发连锁反应：
    
    山火→大面积植物被毁→食草动物饿死或迁移→捕食者饥饿→
    捕食者更频繁攻击AHEI→AHEI大量死亡→
    雨季来临→植被重新生长→食草动物恢复→生态重新平衡

    洪水→低洼巢穴被毁→物资流失→AHEI被迫迁移→
    可能侵入其他部落领地→部落冲突→社会动荡

1.5 生态数据持久化（世界文件夹存储）

    生态统计数据（各物种数量）随世界存档保存，存储在世界文件夹的
    ecosystem_data.json 文件中：
    ```json
    {
      "plant_count": 4523,
      "herbivore_count": 187,
      "predator_count": 34,
      "ahei_count": 78,
      "last_update_time": 12345.6
    }
    ```
    该文件在游戏时间每推进一天时更新一次。
    加载世界时，EcosystemManager读取此文件恢复生态数据。

2.1 植物生成规则

    所有植物按照以下规则程序化生成：
        - 每种地形类型有对应的专属植物群落
        - 温度、湿度、土壤类型决定具体物种分布
        - 同种植物倾向于成片生成（模拟自然群落）
        - 植物会生长、繁殖、死亡，不是静态装饰
        - 被砍伐或采集后，在一定条件下可再生
        - 每棵植物都是程序化生成的独一无二实例
          （树干弯曲度、树枝分叉角度、树叶密度均不同）

    采集：浆果直接摘取（徒手），块茎需用棍子或手挖，树皮用石刀剥，松脂用容器接

    药用：将特定植物碾碎或煮沸制成药膏或药汤

2.8 Godot实现（PackedScene实例化与随机变形）

    在Godot中，植物使用PackedScene预定义基础结构，实例化时随机调整参数：
    
    ```gdscript
    # TreeSpawner.gd
    @export var tree_scenes: Array[PackedScene]  # 不同树种的预设场景
    
    func spawn_tree(world_pos: Vector3, tree_type: String) -> Node3D:
        var scene = tree_scenes_by_type[tree_type]
        var instance = scene.instantiate()
        # 随机缩放
        var scale_factor = randf_range(0.8, 1.2)
        instance.scale = Vector3(scale_factor, scale_factor, scale_factor)
        # 随机旋转（让树枝朝向不同方向）
        instance.rotation_degrees.y = randf_range(0, 360)
        # 微调树干颜色
        var trunk = instance.get_node("Trunk")
        if trunk and trunk is MeshInstance3D:
            var mat = trunk.get_surface_override_material(0)
            if mat:
                mat.albedo_color = trunk_color.lerp(
                    Color(0.5, 0.3, 0.1), randf_range(-0.1, 0.1))
        # 添加到世界
        add_child(instance)
        instance.global_position = world_pos
        return instance
    ```

    对于大规模植被，可使用MultiMeshInstance3D来优化渲染性能：
    ```gdscript
    # 使用MultiMesh批量渲染草或灌木
    var multimesh = MultiMesh.new()
    multimesh.mesh = grass_mesh
    multimesh.instance_count = 10000
    for i in range(multimesh.instance_count):
        var pos = get_random_grass_position()
        var t = Transform3D(Basis(), pos)
        multimesh.set_instance_transform(i, t)
    ```

3.1 矿物分布总则（按地形+深度）

    矿物的分布严格遵循地质规律：海拔决定矿脉类型，深度决定开采难度。
    矿脉从地表一直延伸到地下，可能需要先挖开覆土和普通岩石才能接触到深处的矿脉。
    所有矿石在生成时均附带基于坐标噪声的随机外观微调，因此没有两块完全相同的矿石。

3.6 矿物识别线索

    每种矿物在视觉上有独特的可辨识特征，AHEI可以通过观察来寻找：
    - 孔雀石：鲜艳蓝绿色，在地表即可看到
    - 赤铁矿：红褐色，摸起来有粗糙感
    - 金矿：永不褪色的亮黄色颗粒
    - 铜矿：岩石上蓝绿色的斑驳痕迹
    - 煤矿：纯黑色的岩层，比岩石轻
    - 燧石：灰色有光泽，常裸露在地表
    - 盐：白色结晶，水边更易找到

3.7 Godot实现（不规则矿石簇生成）

    在Godot中，矿石簇通过代码创建多个MeshInstance3D球体，以父节点组织：
    
    ```gdscript
    # OreSpawner.gd
    func spawn_ore_cluster(world_pos: Vector3, ore_data: Dictionary) -> Node3D:
        var cluster = Node3D.new()
        cluster.name = ore_data["name"] + "_cluster"
        
        # 主矿块
        var main = MeshInstance3D.new()
        main.mesh = SphereMesh.new()
        main.mesh.radius = randf_range(0.3, 0.6)
        main.mesh.height = main.mesh.radius * 2
        main.mesh.radial_segments = 8
        main.mesh.rings = 6
        var mat = StandardMaterial3D.new()
        mat.albedo_color = ore_data["color"]
        main.set_surface_override_material(0, mat)
        main.position = world_pos
        cluster.add_child(main)
        
        # 随机附加1-3个小矿块
        for i in range(randi_range(1, 3)):
            var sub = MeshInstance3D.new()
            sub.mesh = SphereMesh.new()
            sub.mesh.radius = randf_range(0.15, 0.4)
            sub.mesh.height = sub.mesh.radius * 2
            sub.mesh.radial_segments = 6
            sub.mesh.rings = 4
            sub.set_surface_override_material(0, mat)
            sub.position = Vector3(
                randf_range(-0.35, 0.35),
                randf_range(-0.2, 0.35),
                randf_range(-0.35, 0.35)
            )
            cluster.add_child(sub)
        
        add_child(cluster)
        return cluster
    ```

3.8 矿物数据持久化（世界文件夹存储）

    矿物作为地形的一部分，其分布数据在区块生成时确定，并随地形区块文件
   （chunk_<x>_<z>.dat）一起保存。当AHEI开采矿物后，区块文件中的
    资源标记会被更新，记录该位置的矿物已被采空。
    
    这确保了矿物状态（已开采/未开采）在世界重新加载后仍然保持。

5.1 PackedScene的使用与随机化

    每种植物和动物都应创建一个PackedScene作为模板：
        - 树木：包含Trunk(CylinderMesh)和Canopy(ConeMesh)子节点
        - 灌木：包含多个SphereMesh子节点
        - 动物：包含身体模型和动画树
    
    实例化时通过脚本随机修改scale、rotation、颜色参数，
    确保相同物种的个体之间也有差异。

5.2 大规模植被的性能优化（MultiMeshInstance3D）

    对于高密度的草、灌木等，使用MultiMeshInstance3D：
        - 设置mesh和material
        - 设置instance_count
        - 为每个实例计算世界坐标和轻微的高度偏移
        - 通过visible_range控制LOD距离
    
    示例：
    ```gdscript
    func build_grass_multimesh() -> void:
        var mmin = MultiMeshInstance3D.new()
        var mm = MultiMesh.new()
        mm.mesh = grass_quad_mesh
        mm.instance_count = GRASS_COUNT
        mm.visible_instance_count = -1  # 显示全部
        for i in range(GRASS_COUNT):
            var pos = get_valid_grass_position()
            var t = Transform3D(Basis().rotated(Vector3.UP, randf()*PI*2),
                               pos + Vector3(0, randf()*0.1, 0))
            mm.set_instance_transform(i, t)
        mmin.multimesh = mm
        add_child(mmin)
    ```

5.3 矿物碰撞体与交互

    矿石簇添加Area3D子节点用于检测AHEI的接近和交互：
    ```gdscript
    func setup_ore_collision(cluster: Node3D) -> void:
        var area = Area3D.new()
        var shape = CollisionShape3D.new()
        shape.shape = SphereShape3D.new()
        shape.shape.radius = 1.0  # 交互范围
        area.add_child(shape)
        area.body_entered.connect(_on_body_entered_ore)
        cluster.add_child(area)
    ```

5.5 世界文件夹中的实体文件格式

    除了动物，AHEI、AI教师化身、以及未来可能加入的任何实体
    都遵循相同的持久化格式，存储在世界文件夹的 entities/ 目录中。
    
    实体文件的读写由 SaveManager 负责：
    ```gdscript
    func save_entity(entity: Node3D) -> void:
        var world_path = GameState.current_world_path
        var file_path = world_path + "/entities/" + entity.entity_id + ".json"
        var data = {
            "id": entity.entity_id,
            "type": entity.entity_type,
            "position": [entity.global_position.x, entity.global_position.y, entity.global_position.z],
            # ... 其他状态数据
        }
        var file = FileAccess.open(file_path, FileAccess.WRITE)
        file.store_string(JSON.stringify(data))
        file.close()
    
    func load_entity(entity_id: String) -> Dictionary:
        var world_path = GameState.current_world_path
        var file_path = world_path + "/entities/" + entity_id + ".json"
        if not FileAccess.file_exists(file_path):
            return {}
        var file = FileAccess.open(file_path, FileAccess.READ)
        var data = JSON.parse_string(file.get_as_text())
        file.close()
        return data
    ```
