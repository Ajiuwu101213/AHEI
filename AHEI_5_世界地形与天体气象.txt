第一章  地形生成系统
================================================================================

1.1 生成原则（连续高度场，非方块）

    AHEI世界的地形不使用方块网格。地形是连续的、平滑起伏的高度场。
    每一个坐标(x,z)都对应一个唯一的高度值y，形成无限分辨率的地表。
    在Godot 4.x中，地形网格通过SurfaceTool类动态构建ArrayMesh实现。
    
    地形数据存储在世界文件夹的 terrain/ 目录中，每个区块一个 .dat 文件。
    区块文件命名规则：chunk_<x>_<z>.dat。
    这种设计确保整个世界的所有数据自包含在一个文件夹内，便于备份、迁移和删除。

1.2 多层柏林噪声叠加算法

    地形由三层柏林噪声叠加生成，每一层负责不同尺度的地理特征：

    第一层——大陆尺度噪声（低频，高振幅）：
        噪声频率：0.005（约每200单位一个周期）
        振幅：28单位
        作用：决定大陆与海洋的宏观分布，形成山脉主脊线
    
    第二层——区域尺度噪声（中频，中振幅）：
        噪声频率：0.02（约每50单位一个周期）
        振幅：10单位
        作用：在大陆基础上添加丘陵、河谷、盆地等区域地形
    
    第三层——局部尺度噪声（高频，低振幅）：
        噪声频率：0.08（约每12.5单位一个周期）
        振幅：4单位
        作用：添加细小的地貌起伏、岩石露头、小土丘
    
    最终高度 = 第一层噪声 × 28 + 第二层噪声 × 10 + 第三层噪声 × 4

    噪声函数实现（GDScript）：
    ```gdscript
    static func perlin_noise(x: float, z: float, seed_val: int) -> float:
        var noise: float = 0.0
        var freq: float = 0.015
        var amp: float = 18.0
        for i in range(5):
            noise += amp * (0.5 - 0.5 * cos(freq * (x + seed_val) + z * 0.7))
            noise += amp * (0.5 - 0.5 * sin(freq * (z - seed_val) - x * 0.3))
            freq *= 2.1
            amp *= 0.45
        return noise
    ```

1.3 程序化生成的独特性（没有两块相同的石头）

    基于噪声函数的地形生成保证了世界每一处都是独一无二的。
    任何两块区域的高度场、坡度走向、地表材质纹理都因坐标输入不同而
    产生不同噪声采样值。天然岩石的形态、大小、表面裂纹走向均由局部
    噪声值驱动的程序化几何变形实时生成，因此世界上没有两块完全相同的石头。
    同理，每一棵树的树干弯曲度、树枝分叉角度、树叶密度分布也都由坐标
    和树种参数通过噪声函数实时计算。

1.4 分块加载与无限世界

    世界采用分块(Chunk)管理：
        每块大小：50×50单位
        加载半径：3块（以玩家或观察目标为中心）
        只有加载范围内的区块参与渲染和物理计算
        远处区块仅保留高度场和资源分布的抽象数据
    
    在Godot中，分块通过以下方式实现：
        - 每个块为一个独立的MeshInstance3D节点
        - ChunkManager脚本管理所有块的加载/卸载
        - 使用Thread或WorkerThreadPool在后台生成块数据
        - 块的可见性由距离计算决定，超出范围的块被queue_free()

1.5 世界种子与可复现性

    世界种子是一个整数，作为所有噪声函数的输入源。
    相同的种子永远生成相同的地形、相同的河流路径、相同的资源分布。
    世界种子存储在世界文件夹的 world_data.json 中：
    ```json
    {
      "world_name": "我的世界",
      "seed": 123456789,
      "game_time": 0.0,
      "time_ratio": 1.0,
      "weather": "clear",
      "season": "spring",
      "version": "1.0.0"
    }
    ```
    加载世界时，从 world_data.json 读取种子，用于生成或校验地形区块。
    可在创建新世界时手动输入种子或使用随机种子。

1.6 地形数据持久化（世界文件夹存储）

    地形区块数据持久化保存，避免每次加载世界时重新生成整个地形。
    区块文件存储在世界文件夹的 terrain/ 子目录中。
    
    文件命名规则：chunk_<x>_<z>.dat
        - x 和 z 是区块的网格坐标（整数），以区块大小为单位。
        - 例如：chunk_0_0.dat 代表中心区块。
    
    文件格式：二进制（使用 FileAccess 的 WRITE 模式）
        - 区块头：区块坐标(x, z)、区块大小、版本号（各4字节）
        - 高度图：一个大小为 (CHUNK_SIZE+1)×(CHUNK_SIZE+1) 的浮点数组
        - 材质信息（可选）：每个顶点对应的地形材质ID
        - 资源标记（可选）：矿物、树木等资源的位置和类型
    
    加载流程：
        1. 当区块进入加载半径时，ChunkManager 检查 terrain/ 文件夹中
           是否存在对应的 .dat 文件。
        2. 如果存在，读取区块数据，使用 SurfaceTool 快速重建网格。
        3. 如果不存在，按种子和噪声算法生成高度场，创建网格，
           并保存为新 .dat 文件至 terrain/ 文件夹。
        4. 区块离开加载半径时，卸载网格节点，但保留 .dat 文件以备再次加载。
    
    优势：
        - 避免重复计算：已生成的区块被永久保存
        - 兼容性：区块文件独立于引擎，可被外部工具解析或编辑
        - 世界完整性：整个世界的所有信息都在一个文件夹内
    
    每个区块文件大小估算：(51×51) × 4字节 ≈ 10 KB，
    对于1000个区块约10 MB，性能可接受。

第二章  13种地形类型
================================================================================

2.1 地形分类判定规则

    地形类型由两个因素自动判定：
        高度（海拔）：基准海平面为0
        坡度（地表倾斜角度）：由高度场的梯度计算
    
    GDScript判定函数：
    ```gdscript
    func classify_terrain(x: float, z: float) -> String:
        var h = get_height(x, z)
        var slope = get_slope(x, z)
        # ... 根据h和slope返回类型
    ```
    
    连续的判定阈值使地形过渡天然平滑，不存在硬性边界。

2.2 深海
    高度：-50 ~ -20米
    坡度：无限制
    特征：深蓝色水体，完全黑暗的海底，极高水压
    资源：海底矿物（后期科技可开采）、深海鱼类
    危险：高压、低温、溺水
    AHEI影响：无法直接进入，后期可能需要潜水设备

2.3 浅海
    高度：-20 ~ -2米
    坡度：< 5°
    特征：浅蓝透明水体，可见海底沙地、珊瑚礁、海带森林
    资源：鱼类、贝类、海带、珍珠
    危险：溺水（水深超过AHEI身高）、洋流
    AHEI影响：可以游泳，但体力消耗大，需要浮出水面换气

2.4 沙滩/河岸
    高度：-2 ~ 0米
    坡度：< 5°
    特征：金黄色细沙、贝壳散布、卵石区域
    资源：沙子（玻璃原料）、黏土、盐、贝类
    危险：极低
    建巢适宜度：30%

2.5 平原/草地
    高度：0 ~ 10米
    坡度：< 10°
    特征：绿色草地、灌木丛、偶有橡树、果树林
    资源：浆果、药草、小型猎物（兔子等）、燧石
    危险：极低（可能有伏击捕食者藏于灌木）
    建巢适宜度：90%

2.6 丘陵
    高度：10 ~ 30米
    坡度：10° ~ 25°
    特征：起伏的绿色山丘、岩石露头增多、树木密度增加
    资源：铜矿（浅层）、锡矿（浅层）、燧石、果树、蘑菇
    危险：低（坠落风险轻微）
    建巢适宜度：70%

2.7 山地
    高度：30 ~ 60米
    坡度：25° ~ 40°
    特征：岩石显著增多、树木变稀疏、山间溪流
    资源：铁矿（中层）、银矿（中层）、煤矿（中层）、山羊
    危险：中（坠落伤害、氧气略稀薄）
    建巢适宜度：40%

2.8 高山
    高度：60 ~ 100米
    坡度：> 40°
    特征：裸露岩石为主、雪线以上积雪覆盖、冰川遗迹
    资源：金矿（深层）、宝石、稀有矿物
    危险：高（坠落致死、严寒、缺氧）
    建巢适宜度：10%（仅崖顶或洞穴）

2.9 悬崖
    高度：任意
    坡度：> 60°
    特征：陡峭的岩壁或断裂面，暴露出地层剖面
    资源：矿脉截面直接可见（铜/铁/金等可能暴露）
    危险：极高（坠落致死）
    建巢适宜度：5%（仅崖顶）

2.10 火山
    高度：50 ~ 80米
    坡度：30° ~ 50°
    特征：黑褐色火山岩、地热喷口、熔岩流遗迹
    资源：黑曜石、硫磺、金矿、钻石
    危险：极高（喷发、熔岩、高温、有毒气体）
    建巢适宜度：0%

2.11 沼泽
    高度：-5 ~ 5米
    坡度：< 5°
    特征：墨绿色浑浊水域、泥炭地、枯树、瘴气
    资源：泥炭（燃料）、黏土、毒蘑菇、药用真菌
    危险：中（陷坑、瘴气致病、蚊虫传播病原体）
    建巢适宜度：20%

2.12 森林
    高度：0 ~ 30米
    坡度：< 25°
    特征：密集的高大树木、多层树冠、林下阴暗湿润
    资源：木材、果实、蘑菇、猎物（鹿等）
    危险：中（伏击捕食者藏身暗处、容易迷路）
    建巢适宜度：80%

2.13 冻原/雪地
    高度：40 ~ 100米（或高纬度）
    坡度：< 20°
    特征：白色积雪覆盖、低矮耐寒植被、永久冻土
    资源：偶有金属矿暴露、耐寒动物（雪兔、冰狐）
    危险：高（严寒导致失温、暴风雪）
    建巢适宜度：30%

2.14 洞穴系统

    生成位置：山体侧面或悬崖底部
    内部结构：多层隧道网络，连接多个洞室
    洞室类型：小洞室（3-5米直径）/ 大洞室（10-20米）/ 矿脉洞室（暴露多种矿物）
    环境特征：完全黑暗、湿度高、温度恒定
    危险：深度>50米有缺氧风险（体力消耗加速）、洞顶可能坍塌
    特殊资源：发光蘑菇（天然光源）、蝙蝠群（食物来源）

2.15 地形对AHEI行为的影响

    移动策略：偏好平坦地形以节省体力；受伤时避开陡坡；带幼崽时选最安全路线
    觅食策略：平原和森林是主要觅食区；旱季迁移到水边；冬季从高山下到低地
    防御策略：巢穴偏好丘陵顶部或悬崖边缘（视野开阔、易守难攻）
    采矿策略：铜锡在丘陵区；铁银需进山地；金必须深入地下或高海拔

第三章  水体系统
================================================================================

3.1 河流生成算法

    河流从高海拔区域（>30米）随机选择的发源点出发，
    沿地形坡度的最陡方向向下延伸，最终汇入海洋或湖泊。
    
    上游（>30m）：湍急山溪，流速3-5 m/s，宽1-3m，浅0.3-1m
    中游（10-30m）：中等河流，流速1-3 m/s，宽5-10m，深1-2m
    下游（0-10m）：平缓河流，流速0.3-1 m/s，宽10-30m，深2-5m
    
    支流在路径相交处汇入主流。河流两岸自动生成湿度增高的河岸地形。
    
    Godot实现：
    ```gdscript
    func generate_river(start_x: float, start_z: float) -> Array:
        var points = []
        var x = start_x
        var z = start_z
        for step in range(500):  # 最多500步
            var h = get_height(x, z)
            points.append(Vector3(x, h + 0.15, z))
            # 计算梯度方向
            var grad = calculate_gradient(x, z)
            x -= grad.x * 0.08
            z -= grad.z * 0.08
            if abs(x) > world_size/2 or abs(z) > world_size/2: break
            if h < -1: break  # 到达水域
        return points
    ```

3.2 河流物理属性（流速/宽度/深度）

    在不同河段，水流的速度、宽度和深度差异显著：
        上游：流速3-5m/s, 宽1-3m, 深0.3-1m, 水体清澈浅蓝, 湍急水声
        中游：流速1-3m/s, 宽5-10m, 深1-2m, 蓝绿色, 中等流水声
        下游：流速0.3-1m/s, 宽10-30m, 深2-5m, 深蓝/浑浊, 低沉流动声
    
    河流视觉表现：
        在Godot中使用LineMesh或沿路径放置多个MeshInstance3D
        材质：使用带透明度的蓝色StandardMaterial3D
        可叠加粒子系统模拟水花

3.3 湖泊生成

    在内陆低洼盆地积水形成，水体相对静止。
    深度通常在2-20米之间，周边形成湿地环境。

3.4 海洋生成

    海洋占据世界最低处（高度<0区域自动填充为海洋）。
    在Godot中，海洋为一个巨大的PlaneMesh平面，
    位置在y=0（海平面），使用带透明度+波动效果的水体Shader。
    海水有盐度，不可直接饮用。

3.5 水体物理（浮力/阻力/溺水）

    浮力：在Area3D的body_entered信号中，对进入水体的物体
          施加向上的力 = volume * 1000 * 9.8
    阻力：水体中移动速度降至陆地的25%
    溺水：水深超过AHEI身高且无法游回→溺水30秒后health扣减
    
    Godot实现：
    ```gdscript
    # 在水体Area3D的脚本中
    func _on_body_entered(body: Node3D) -> void:
        if body.has_method("enter_water"):
            body.enter_water(self)
    
    func _on_body_exited(body: Node3D) -> void:
        if body.has_method("exit_water"):
            body.exit_water(self)
    ```

3.6 水中声音传播

    水中声音传播速度约为空气的4倍，可听距离也扩展4倍。
    但音色失真严重（高频被吸收），方向定位困难。

3.7 水体对AHEI的影响

    饮水：河流和湖泊是主要饮用水源。
    渡河：水流速度>2m/s时AHEI可能被冲走。
    食物：河流和浅海可生成鱼类、贝类等。
    领地：河流是天然屏障，不同部落可能以河流为界。

第四章  天体系统（全部动态，不固定）
================================================================================

4.1 太阳（动态东升西落）

    在Godot中使用DirectionalLight3D作为太阳光源。
    创建sun_mover.gd脚本，使太阳围绕世界旋转。
    
    日出：东方地平线，颜色温暖金黄（灯光颜色设为Color(1.0, 0.8, 0.5)）
    正午：南方最高点，光照最强，色温偏白（灯光颜色设为Color(1.0, 1.0, 0.95)）
    日落：西方地平线，颜色变为橙红（灯光颜色设为Color(1.0, 0.5, 0.3)）
    夜间：太阳完全在地平面以下，光照仅来自月光和星光
    
    ```gdscript
    # sun_mover.gd 关键代码
    func _process(delta: float) -> void:
        var angle = GameState.time_of_day * 360.0 / DAY_LENGTH
        self.rotation_degrees = Vector3(angle - 90, 0, 0)
        update_light_color()
    ```

4.2 光照与大气散射模拟

    Godot的WorldEnvironment节点配置：
        - Environment的background mode设为Sky
        - Sky使用ProceduralSkyMaterial
        - 根据太阳角度动态更新sky_materialのsun_angle参数
        - Ambient Light颜色随昼夜变化：白天Color(0.3,0.3,0.4)，夜晚Color(0.05,0.05,0.1)

4.3 月亮（阴晴圆缺周期）

    月亮有完整的月相周期（约每30个游戏天一个完整循环）：
        新月→上弦月→满月→下弦月→新月
    
    Godot实现：
        - 创建一个Moon节点（Sprite3D或MeshInstance3D）
        - 根据GameState中的日期计算当前月相
        - 满月之夜：调整Environmentのambient_light_energy增加
        - 新月之夜：最暗

4.4 星星（程序化夜空点阵）

    在Sky Material中使用程序化噪声生成星星。
    星星的亮度随月相变化（满月时星暗，新月时星亮）。
    星星位置由世界种子决定，固定不变（可用于导航）。

4.5 天体对AHEI的影响

    太阳：方向判断（东西方向）、时间感知
    月亮：夜间照明强弱、月相可能成为文化符号
    星星：方向识别（没有北极星概念，但可识别固定星点）


================================================================================
第五章  云层系统（动态）
================================================================================

5.1 程序化体积云生成

    在Godot中可采用两种方案：
    
    方案A（初期推荐）：使用GPUParticles3D
        - 创建多个CloudCloudParticle粒子系统
        - 每个粒子是一个半透明白色平面
        - 粒子在玩家周围生成，随风移动
    
    方案B（后期优化）：使用Volumetric Fog + 噪声（Godot 4.x原生支持）
        - 在WorldEnvironment中配置volumetric_fog
        - 使用噪声纹理驱动云层形状

5.2 云的飘动（随风）

    云的位置随风向和风速实时移动：
    ```gdscript
    func _process(delta: float) -> void:
        position.x += GameState.wind.x * delta
        position.z += GameState.wind.z * delta
        # 超出边界则重置到另一侧
    ```

5.3 云的聚集与降雨触发

    当云层密度超过临界值（可通过计算区域内云粒子数量判断），触发降雨。
    雨的强度由云层厚度决定。
    降雨后云层变薄，形成自然的降雨循环。

5.4 云对光照的影响

    云层通过WorldEnvironmentのvolumetric_fog或调整阳光强度来影响光照。
    厚云时DirectionalLight3Dのenergy降低，场景变暗（阴天效果）。


================================================================================
第六章  风系统（动态）
================================================================================

6.1 气压差驱动的空气流动

    风由世界中的温度差异产生的气压差驱动。
    温暖区域的空气上升（低气压），寒冷区域的空气下降（高气压）。
    空气从高气压区域流向低气压区域，形成风。
    
    风速范围：0-30 m/s
    风向随气压分布的持续变化而改变。

6.2 风的方向与强度变化

    风不是固定的——它随气压分布的持续变化而改变。
    在GDScript中，风存储在GameState单例中，提供全局访问：
    ```gdscript
    # GameState.gd
    var wind: Vector3 = Vector3(1.0, 0.0, 0.0)  # 风向+强度向量
    ```

6.3 风的影响
    云移动：风推动云层漂移
    物体晃动：强风下树木枝叶摇摆（在植物着色器中加入风的影响）
    声音传播：顺风方向声音可听距离+30%，逆风-30%
    气味扩散：风将气味吹向下风向
    体感温度：风冷效应——风速越大，体感温度越低
    
    ```gdscript
    func calculate_wind_chill(base_temp: float, wind_speed: float) -> float:
        # 风冷指数简化公式
        return base_temp - wind_speed * 0.5
    ```

6.4 风与火的交互

    风推动火焰蔓延方向，加速火势扩散。
    强风可使小火熄灭（吹灭），也可使大火迅速失控（供氧）。


================================================================================
第七章  昼夜与季节循环
================================================================================

7.1 昼夜循环

    默认10游戏分钟=1游戏天（可在GameState.DAY_LENGTH中调整）。
    昼夜循环连续运行，无加载界面打断。
    
    白天：太阳在天空可视，DirectionalLight3D能量=1.0
    黄昏：太阳接近地平线，灯光颜色变暖，能量降至0.5
    夜晚：太阳在地平线下，灯光能量=0，仅靠环境光照亮
    黎明：太阳重新升起，灯光颜色从暖变白

7.2 昼夜对AHEI的影响

    白天活跃：大部分AHEI在白天觅食、社交、建造
    夜行性演化：如果某个种群长期面临白天捕食者压力，
                 部分个体可能演化出夜行性
    睡眠周期：AHEI通常在夜晚睡眠，但夜行性个体相反

7.3 季节循环

    默认100游戏分钟=1游戏年（可在GameState.YEAR_LENGTH中调整）。
    四季连续过渡，无生硬切换。
    
    春季（0%-25%）：温度从寒冷稳步回升，植物发芽
    夏季（25%-50%）：温度最高，食物最丰富
    秋季（50%-75%）：温度开始下降，果实成熟
    冬季（75%-100%）：温度最低，食物极度短缺

7.4 四季的环境变化

    春季：草地变绿，果树开花，食草动物产仔。
        通过修改地形material的颜色参数实现（tint变绿）。
    夏季：草地茂盛，果实挂满枝头，昆虫活跃，雷雨频繁。
    秋季：树叶变金黄与红色，通过修改树木shaderのhue参数实现。
    冬季：落叶树光秃，地面可能被雪覆盖，河流结冰。

7.5 季节对AHEI生存策略的影响

    春季：种群数量恢复期，建巢、交配频繁
    夏季：食物最大化期，育幼、建造、技术研发
    秋季：关键储存期，大量采集和囤积
    冬季：纯粹生存期，只有储存充足的个体和部落能活到明年春天

第八章  气候与自然灾害
================================================================================

8.1 晴天/阴天/雨天

    晴天：正常光照和温度
    阴天：调整DirectionalLight3D能量降低40%
    雨天：视觉距离降至正常60%，使用粒子系统模拟雨滴
    
    雨天的影响：
        - 体温下降加快
        - 水分消耗减慢（空气湿润）
        - 地面湿滑（摩擦系数降低）
        - 雨后植物生长加速

8.2 暴风雨/暴风雪

    在Godot中通过以下组合实现：
        - 粒子系统：大量高速雨滴/雪花
        - 风：速度提升到20-30 m/s
        - 光照：DirectionalLight3D能量大幅降低
        - WorldEnvironment：volumetric_fog密度增加
    
    暴风雪特有的：
        - 视觉距离降至10%
        - 体温下降极快
        - 雪粒子替换雨粒子

8.3 山火

    触发：随机（干旱季节概率升高）或被AHEI失火引发
    实现：使用粒子系统模拟火焰，沿风向蔓延
    后果：区域内植被被毁、AHEI可能被烧死
    恢复：烧毁区域在雨后重新生长

8.4 洪水

    触发：持续暴雨导致河流水位暴涨
    实现：提升水体高度，检测淹没建筑和巢穴
    后果：低洼区域被淹没、物资流失、巢穴被毁

8.5 干旱

    触发：连续多个季节无降雨
    后果：植物枯死、水源干涸、食物链崩溃

8.6 地震（后期可扩展）

    极少概率的随机事件
    后果：地面震动（通过Camera3Dのshake实现）、建筑物坍塌

第九章   Godot 4.x 实现技术要点
================================================================================

9.1 SurfaceTool网格构建

    地形网格使用SurfaceTool类动态构建：
    ```gdscript
    func build_terrain_chunk(chunk_x: int, chunk_z: int) -> ArrayMesh:
        var st = SurfaceTool.new()
        st.begin(Mesh.PRIMITIVE_TRIANGLES)
        # 添加顶点和颜色
        for z in range(CHUNK_SIZE + 1):
            for x in range(CHUNK_SIZE + 1):
                var world_x = chunk_x * CHUNK_SIZE + x
                var world_z = chunk_z * CHUNK_SIZE + z
                var y = get_height(world_x, world_z)
                st.set_color(get_terrain_color(y))  # 高度→颜色
                st.add_vertex(Vector3(x, y, z))
        # 添加索引
        var rows = CHUNK_SIZE + 1
        var cols = CHUNK_SIZE + 1
        for r in range(rows - 1):
            for c in range(cols - 1):
                var i0 = r * cols + c
                var i1 = r * cols + c + 1
                var i2 = (r + 1) * cols + c
                var i3 = (r + 1) * cols + c + 1
                st.add_index(i0); st.add_index(i2); st.add_index(i1)
                st.add_index(i1); st.add_index(i2); st.add_index(i3)
        st.generate_normals()
        st.commit()
        return st.commit()
    ```

9.2 顶点颜色着色器设置

    为地形材质创建StandardMaterial3D资源：
        - vertex_color_use_as_albedo = true
        - shading_mode = BaseMaterial3D.SHADING_MODE_PER_PIXEL
        - roughness = 0.9
        - metallic = 0.1
    
    这确保了地形颜色由顶点颜色驱动，随高度呈现平滑渐变。

9.3 地形碰撞体生成

    为每个地形块添加物理碰撞：
    ```gdscript
    var static_body = StaticBody3D.new()
    var collision_shape = CollisionShape3D.new()
    var shape = ConcavePolygonShape3D.new()
    shape.set_faces(terrain_mesh.get_faces())
    collision_shape.shape = shape
    static_body.add_child(collision_shape)
    add_child(static_body)
    ```
    
    碰撞体使AHEI能行走在地形表面，受重力影响不会穿透地面。

9.4 WorldEnvironment配置

    创建Environment资源，配置：
        - background_mode = Environment.BG_SKY
        - sky = ProceduralSkyMaterial
        - volumetric_fog_enabled = true（用于云和雾）
        - glow_enabled = true（用于太阳光晕）
        - ambient_light_color = Color(0.3, 0.3, 0.4)（白天）或Color(0.05, 0.05, 0.1)（夜晚）

9.5 粒子系统与天气效果

    雨：GPUParticles3D，粒子材质为细长白色平面，重力方向向下
    雪：GPUParticles3D，粒子材质为白色圆点，下落速度慢，有横向飘动
    云：多个粒子系统或volumetric fog
    火焰：GPUParticles3D，粒子材质使用火焰纹理，由风向驱动蔓延方向

9.6 地形区块文件读写（世界文件夹持久化）

    区块数据使用FileAccess进行二进制读写：
    ```gdscript
    func save_chunk(chunk_x: int, chunk_z: int, height_data: PackedFloat32Array) -> void:
        var world_path = GameState.current_world_path
        var file_path = world_path + "/terrain/chunk_%d_%d.dat" % [chunk_x, chunk_z]
        DirAccess.make_dir_recursive_absolute(world_path + "/terrain")
        var file = FileAccess.open(file_path, FileAccess.WRITE)
        if not file: return
        # 写入区块头
        file.store_32(chunk_x); file.store_32(chunk_z)
        file.store_32(CHUNK_SIZE); file.store_32(1)  # 版本号
        # 写入高度数据
        for height in height_data:
            file.store_float(height)
        file.close()
    
    func load_chunk(chunk_x: int, chunk_z: int) -> PackedFloat32Array:
        var world_path = GameState.current_world_path
        var file_path = world_path + "/terrain/chunk_%d_%d.dat" % [chunk_x, chunk_z]
        if not FileAccess.file_exists(file_path):
            return PackedFloat32Array()  # 空数组表示需要重新生成
        var file = FileAccess.open(file_path, FileAccess.READ)
        if not file: return PackedFloat32Array()
        # 读取区块头
        var cx = file.get_32(); var cz = file.get_32()
        var size = file.get_32(); var version = file.get_32()
        # 读取高度数据
        var count = (size + 1) * (size + 1)
        var height_data = PackedFloat32Array()
        height_data.resize(count)
        for i in range(count):
            height_data[i] = file.get_float()
        file.close()
        return height_data
    ```

9.7 地形修改层（模组可破坏地形接口）

    为了支持模组对地形进行修改（如挖掘、填充），每个区块额外维护一个
    “修改高度图”（modification_map），存储在区块文件的第二部分。
    
    修改层结构：
        - 与原始高度图相同尺寸的浮点数组
        - 正值 = 在该顶点增加了高度（堆土）
        - 负值 = 在该顶点减少了高度（挖掘）
        - 0 = 未修改
    
    渲染时，最终高度 = 原始高度 + 修改高度。
    SurfaceTool在构建网格时同时读取两份数据。
    
    模组可通过 `WorldManager.modify_terrain(position, delta)` 接口
    对指定坐标的地形进行修改，无需直接操作区块文件。
    
    这为模组添加铲子、炸药、钻头等地形修改工具提供了底层支持。
    同时也为未来扩展太空维度（微重力+真空环境）预留了“世界区域”
    的概念——每个世界区域可以有不同的物理法则和生成规则。
